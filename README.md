# 🥋 Bushido Discipline OS — سند عملیاتی، توسعه و استقرار

> **نسخه استقرار:** ۳.۰ (Production & Vercel Native)  
> **پشته فنی:** React 18 + Vite + Tailwind CSS + Express (Node.js) + Prisma / PostgreSQL / In-Memory Fallback  
> **رویکرد داده‌ها:** آفلاین‌محور (Offline-First) با ذخیره‌سازی فوری در `localStorage` و همگام‌سازی ابری

---

## ۱. پیش‌نیازها و راه‌اندازی محلی

### نصب وابستگی‌ها
```bash
npm install
```

### اجرای تست‌های خودکار (سبک و سریع)
تست‌های خودکار شامل محاسبات ریاضی دیسیپلین، فرمول Pure Streak، مخرج شبح، هش کلمه عبور و قفل‌های امنیتی در کمتر از ۲ ثانیه بدون وابستگی خارجی اجرا می‌شوند:
```bash
npm test
```

### اجرای سرور توسعه (Development)
```bash
npm run dev
```
برنامه روی پورت ۳۰۰۰ اجرا شده و همزمان رابط کاربری (Vite) و API سرور را بالا می‌آورد.

### بیلد پروداکشن
```bash
npm run build
npm start
```

## ۲. متغیرهای محیطی (`.env`) و کانفیگ محیط‌ها

پروژه بوشیدو از سه سطح محیطی شفاف پیروی می‌کند:
1. **توسعه محلی (`NODE_ENV=development`):** تمام قابلیت‌های آزمایشی، شبیه‌سازها و میانبرها فعال هستند.
2. **تست و استیجینگ (`staging`/`test`):** امکان اعتبارسنجی با `ALLOW_TEST_SHORTCUTS=true` جهت تست‌های خودکار و تضمین کیفیت.
3. **پروداکشن نهایی (`production`):** مدل شکست-بسته قطعی (Fail-Closed Absolute Isolation). در پروداکشن، میانبرهای تستی، ورود سریع (Quick Login)، پیامک ساختگی (Mock OTP)، دیباگ OTP و درگاه پرداخت شبیه‌سازی‌شده (Mock Payment) به طور کامل غیرممکن و مسدود هستند (حتی در صورت تنظیم متغیر `ALLOW_TEST_SHORTCUTS=true`). همچنین کلید `JWT_SECRET` هیچ فال‌بکی نداشته و حداقل ۳۲ کاراکتر نیاز دارد، اعتبارنامه‌های پیش‌فرض هاردکدشده برای سوپرادمین وجود ندارند، و فرآیند بیلد هرگز ساختار دیتابیس را دستکاری نمی‌کند.

| نام متغیر | نوع | شرح و کاربرد |
| :--- | :--- | :--- |
| `DATABASE_URL` / `POSTGRES_PRISMA_URL` | اختیاری | آدرس اتصال به PostgreSQL (در صورت عدم تنظیم در محیط غیرپروداکشن، از فایل محلی/حافظه استفاده می‌شود). ساختار دیتابیس هرگز در بیلد تغییر نمی‌کند. |
| `DIRECT_URL` / `POSTGRES_URL_NON_POOLING` | اختیاری | آدرس مستقیم بدون Connection Pool برای مایگریشن‌های رسمی Prisma (`npm run db:migrate:deploy`). |
| `JWT_SECRET` | الزامی در پروداکشن | کلید امضای توکن‌های نشست احراز هویت (بدون هیچ فال‌بک در پروداکشن و با الزام حداقل ۳۲ کاراکتر). |
| `ALLOW_TEST_SHORTCUTS` | غیرفعال در پروداکشن | فعال‌سازی میانبرهای تستی در محیط‌های استیجینگ/تست. در پروداکشن به طور قطعی نادیده گرفته می‌شود (Fail-Closed). |
| `ENABLE_OTP_DEBUG` | غیرفعال در پروداکشن | ارسال کد OTP درون پاسخ API فقط در محیط‌های غیرپروداکشن. در پروداکشن مسدود است. |
| `ENABLE_QUICK_LOGIN` | غیرفعال در پروداکشن | فعال‌سازی دکمه‌های ورود سریع فقط در محیط‌های غیرپروداکشن. در پروداکشن مسدود است. |
| `SUPER_ADMIN_PHONE` / `SUPER_ADMIN_EMAIL` | الزامی برای ادمین پروداکشن | شماره همراه یا ایمیل مدیر ارشد سیستم (در پروداکشن هیچ اکانت پیش‌فرض هاردکدشده‌ای وجود ندارد). |
| `SUPER_ADMIN_PASS` | الزامی برای ادمین پروداکشن | کلمه عبور مدیر ارشد سیستم (حداقل ۸ کاراکتر؛ بدون پیش‌فرض در پروداکشن). |
| `ZARINPAL_MERCHANT_ID` | اختیاری | شناسه مرچنت اختیاری در صورت پیکربندی ارائه‌دهنده درگاه پرداخت واقعی (در پروداکشن پرداخت شبیه‌سازی‌شده غیرممکن است و در غیاب درگاه واقعی، سیستم Fail-Closed عمل می‌کند). |

## ۳. شفاف‌سازی در خصوص داده‌های نمونه ۲۴ روزه (Sample Demo Seed)

> ⚠️ **تذکر بسیار مهم برای کاربر و تیم عملیات:**  
> داده‌های نمونه ۲۴ روزه‌ای که در اولین بارگذاری برای حساب مهمان یا کاربر تازه تعریف می‌شوند، **صرفاً یک سناریوی شبیه‌سازی‌شده (Demo Scenario)** جهت نمایش قابلیت‌های ماتریس ۹۰ روزه، تالار رکوردها، نمودار وفاداری و نحوه عملکرد سنسی هوش مصنوعی هستند.  
> 
> - این داده‌ها نباید با دستاورد واقعی کاربر اشتباه گرفته شوند.
> - به محض اینکه کاربر چرخه اختصاصی جدید خود را بسازد یا داده‌ها را بازنشانی کند، روزشمار از صفر و بر اساس تلاش واقعی او محاسبه می‌گردد.
> - موتور ذخیره‌سازی داده‌های واقعی ثبت‌شده توسط کاربر را تحت هیچ شرایطی با داده‌های دمو جایگزین نخواهد کرد.

## ۴. استقرار روی Vercel و سرورهای بدون سرور (Serverless)

در محیط‌های سرورلس مانند Vercel:
- اگر پایگاه داده PostgreSQL تنظیم نشده باشد، فایل موقت در شاخه مجاز `/tmp/bushido_local_db.json` نگهداری می‌شود.
- برای پایداری ۱۰۰٪ داده‌ها در محیط تجاری، توصیه می‌شود متغیر `DATABASE_URL` (مثلاً از دیتابیس رایگان Neon یا Supabase) در تنظیمات پروژه در Vercel قرار گیرد.
- اندپوینت عمومی `/api/health` تنها وضعیت لایونس و زمان سیستم را برمی‌گرداند.
- اندپوینت `/api/admin/diagnostics` (با احراز هویت ادمین) وضعیت کامل قابلیت‌ها، رم و دیتابیس را گزارش می‌دهد.

## ۵. راهنمای مایگریشن دیتابیس و عدم استفاده از `accept-data-loss` در بیلد

> ⛔ **قانون حیاتی پایداری داده‌ها (Database Safety Rule):**  
> اجرای دستوراتی مانند `prisma db push --accept-data-loss` یا هرگونه اسکریپت همگام‌سازی ساختار دیتابیس درون فرآیند `build`، `vercel-build` یا خطوط CI/CD **اکیداً ممنوع** است.

### چرا این کار در Build/CI خطرناک است؟
1. **پاک شدن ناخواسته داده‌ها (Data Loss):** پرچم `--accept-data-loss` به Prisma اجازه می‌دهد در صورت تغییر نوع ستون یا حذف فیلد، تمام داده‌های قبلی کاربران در آن ستون یا جدول را بدون هشدار دور بریزد (Drop کند).
2. **شکست بیلد در غیاب دسترسی به شبکه:** در زمان Build روی سرورهای ابری، دسترسی به دیتابیس خارجی الزامی نیست و نباید بیلد نرم‌افزار به پایداری شبکه یا دسترسی به پورت دیتابیس گره بخورد.

### روش استاندارد تغییر Schema و مایگریشن:
- **فرآیند بیلد کاملاً ایستا و بدون تغییر دیتابیس:** در فرآیند بیلد (`npm run build` / `vercel-build`) صرفاً `prisma generate` اجرا می‌شود تا کلاینت تایپ‌سیف تولید گردد. بیلد هرگز دیتابیس را جهش نمی‌دهد.
- **اعمال دستی تغییرات فقط در محیط محلی:**  
  ```bash
  npm run db:push
  ```
- **استقرار مایگریشن‌ها در پروداکشن (تک‌مسیر مجاز):**  
  مایگریشن‌ها در پروداکشن صرفاً از طریق دستور رسمی زیر اعمال می‌شوند:
  ```bash
  npm run db:migrate:deploy
  ```

## ۶. مسیریابی کلاینت و مسیرهای مجاز (Client Routing & Canonical Paths)

سامانه بوشیدو از یک روتر بومی و سبک بر بستر History API بدون ریلود کامل صفحه (Client-side Routing) استفاده می‌کند. این سازوکار از کلیدهای Back/Forward مرورگر، ژست‌های سوایپ لبه صفحه در موبایل، میانبرهای PWA (مانند `/` و `/dashboard`) و دیپ‌لینک‌های مستقیم پشتیبانی کامل می‌نماید. مسیرهای ثبت‌شده عبارتند از:
- `/` یا `/battlefield`: میدان نبرد روز جاری و ارزیابی عادات ۵ گانه (مسیر پیش‌فرض `start_url`).
- `/dashboard` (یا نام مستعار `/cycle`): اتاق فرماندهی، ماتریس وفاداری، زنجیره خالص و تحلیل پیشرفت چرخه ۹۰ روزه.
- `/more` یا `/profile` (یا نام مستعار `/settings`): منوی بیشتر، راهنمای مبانی بوشیدو، تنظیمات سامانه و مدیریت پروفایل.
- `/archives` (یا `/more/archives` و مسیرهای میراثی `/database`): کارنامه عملکرد و بایگانی چرخه‌های پیشین.
- `/admin`: کنسول مدیریت ارشد سامانه (تحلیل‌های رشد، کاربران و اشتراک‌ها).
